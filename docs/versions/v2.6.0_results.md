## 3. Improvement verdict

**Improved** (single-seed, CI-separated). M6 beats the M3 pre-JT baseline by cps **+0.118** with
**non-overlapping** bootstrap CIs (M3-hi 0.226 < M6-lo 0.240), collision **−22.7%** (0.185→0.143), reach
+0.033, infeasibility −0.022; the small timeout rise (0.135→0.163) is the net cost of a more active policy.
This is the first navigable learned policy through the differentiable filter on this system (imitation
init BC/DAgger reached ≤0.054; a differentiable terminal alone reached ≤0.012). The enabling change over
the refuted differentiable-terminal attempt was the single flag `detach_filter_coeffs: false→true`, which
removed the filter-Jacobian BPTT gradient explosion (grad_norm_pi max 178k→<2000) that had been clipping
the goal-closing credit away; the BPTT terminal (w_terminal=30) supplies the out-of-window goal credit.

Cross-system note: cps is not commensurable across systems (06_workflow §2.4); this is the quadrotor's
first full-pool result and establishes its baseline — not compared to DI/Unicycle.

## 4. Next axis (suggestions, not commitments)

The residual cps drain splits cleanly by lever (M6 residual diagnostics D1–D4):

- **collision 0.143 is execution-bound, and the torque box is mis-set.** 99.7% of residual collisions are
  infeasible at impact / 85.8% ≥5 steps prior (D2), 97% torque-saturated with 92% box-clip at precursors
  (D4) — the filter demands more corrective torque than ±0.2 delivers. Separately, τ_max=0.2 is
  **inconsistent with the plant**: J and f_max imply arm length 0.100 m, whose coherent torque box is
  τ̄≈0.98 (τ_max is the 1/5 of the plant-coherent value; it was set from an angular-agility target, not
  the thrust/inertia geometry — see docs/versions/v2.6.0/torque_box_plausibility.md). A physically coherent
  re-derivation (proposed τ_max≈1.0) is a **plant correction**, not a performance hack; it requires full
  retraining (dynamics change) and is a candidate next-version axis. Whether the added authority reduces
  collision is a falsifiable hypothesis, not a given.
- **timeout 0.163 is a near-goal settle failure, not a horizon shortage.** 57% of timeouts reach within
  goal_radius but miss the goal-speed criterion (loiter); doubling max_steps is cps-neutral (+0.004,
  converts 21% to goal but adds equal collision) — D1. The targeted lever is a **velocity-aware terminal**
  (extend the §4.4 terminal ‖p_T−g‖ → ‖p_T−g‖ + λ‖v_T‖, one added λ), a minimal single-axis change on the
  winning config.

Both target different drains; the ordering (plant correction vs velocity-aware terminal) is a next-version
open decision. Deployment-distribution reporting (a more-nominal eval IC, which D3 shows would read
collision 0.098 on the |θ₀|<π/6 band) is a separate, non-method reporting choice, tracked but not a
performance axis.
